# 🤖 CarrierAssistent

**Локальный AI-карьерный ассистент для поиска, анализа вакансий и подготовки откликов.**

CarrierAssistent автоматизирует весь основной цикл поиска работы:

**поиск вакансий → сбор и очистка данных → дедупликация → оценка соответствия профилю → генерация сопроводительных писем → сохранение результатов.**

Проект работает локально и использует **Ollama + локальную LLM**, поэтому данные профиля и результаты анализа не требуется отправлять в облачные AI-сервисы.

---

## ✨ Что умеет CarrierAssistent

### 🔍 Автоматический поиск вакансий

Приложение может собирать вакансии из нескольких источников:

* **hh.ru**
* **Remote OK**
* **We Work Remotely**
* ручной импорт вакансии по URL
* ручной ввод текста вакансии

Для источников используется единый интерфейс адаптеров, поэтому новые сайты можно добавлять независимо друг от друга.

---

### 🎯 Оценка соответствия вакансии

Для каждой вакансии локальная LLM сравнивает:

* профиль пользователя;
* требования вакансии;
* hard skills;
* soft skills;
* опыт;
* формальные требования;
* потенциальные пробелы в навыках.

Результатом является оценка соответствия и структурированный анализ.

Главный принцип проекта:

> **Не придумывать опыт, навыки или достижения, которых нет в профиле пользователя.**

Если вакансия требует технологии или опыт, отсутствующие в профиле, система должна учитывать это при оценке.

---

### ✉️ Генерация сопроводительных писем

Для подходящих вакансий CarrierAssistent может автоматически создать персонализированное сопроводительное письмо.

Письмо строится на основе:

* реального профиля пользователя;
* конкретной вакансии;
* найденных совпадений;
* оценки соответствия.

Система ориентирована на содержательные письма без шаблонных клише и выдуманного опыта.

---

### 🗃️ База вакансий

Все найденные вакансии сохраняются в локальную **SQLite** базу.

Для вакансий сохраняются:

* источник;
* внешний ID;
* название;
* компания;
* URL;
* описание;
* зарплата;
* локация;
* формат работы;
* тип занятости;
* дата получения;
* match score;
* результат анализа;
* сопроводительное письмо;
* текущий статус.

Статусы вакансий:

```text
new
analyzed
rejected
sent
```

---

### ♻️ Дедупликация

Система защищает базу от повторного сохранения одной и той же вакансии.

Основной идентификатор:

```text
source + external_id
```

Также используется индекс по URL.

Это позволяет повторно запускать поиск, не создавая большое количество копий уже найденных вакансий.

# 🧠 Локальный AI

CarrierAssistent использует **Ollama** в качестве локального inference-сервера.

Основная модель проекта:

```text
qwen2.5:14b-instruct
```

Модель можно изменить в настройках проекта.

Пример конфигурации:

```python
OLLAMA_MODEL = "qwen2.5:14b-instruct"
```

Параметры генерации подбираются с учётом задачи карьерного анализа:

```text
temperature
top_p
top_k
repeat_penalty
num_ctx
num_predict
```

Низкая температура используется для уменьшения случайности и более строгого следования фактам профиля.

# 📄 Профиль пользователя

Профиль загружается из:

```text
my_profile.docx
```

Файл должен находиться рядом с:

```text
app.py
```

Загрузчик читает:

* обычный текст документа;
* таблицы DOCX.

Пример структуры профиля:

```text
Опыт работы

Навыки

Технологии

Проекты

Образование

Достижения

Дополнительная информация
```

### Важный принцип

Профиль является **источником фактов**.

AI не должен добавлять:

* несуществующий опыт;
* несуществующие проекты;
* технологии, которыми пользователь не владеет;
* вымышленные достижения;
* вымышленные должности.

# 🔎 Источники вакансий

## hh.ru

Поддерживается поиск вакансий через API/HTTP и fallback-механизмы.

Для некоторых сценариев предусмотрен браузерный путь.

Особенности текущей реализации:

* обработка ограничений API;
* HTML fallback;
* устойчивый поиск карточек вакансий;
* поддержка удалённого формата;
* обработка нескольких ключевых слов;
* нормализация результатов.

---

## Remote OK

Поддерживается получение вакансий Remote OK.

Несколько ключевых слов не должны искусственно ограничивать выдачу только первым словом поиска.

---

## We Work Remotely

Используется RSS-лента текущей выдачи.

Важно:

> RSS-лента имеет конечный набор доступных записей. Увеличение количества страниц поиска не создаёт дополнительные вакансии после исчерпания текущей ленты.

---

# 🎯 Целевое количество вакансий

Автопоиск работает с целевым количеством результатов.

Например:

```text
Target: 50 вакансий
```

Система должна учитывать:

```text
найдено
сохранено
дубликаты
ошибки
```

Дубликат не должен считаться новой сохранённой вакансией.

Итоговая логика:

```text
Нужно получить 50 новых вакансий
        ↓
Источник дал 30
        ↓
5 оказались дублями
        ↓
Получено только 25 новых
        ↓
Система продолжает поиск другими доступными источниками
        ↓
пока цель не достигнута
или источники не исчерпаны
```

# 📊 Анализ вакансий

Каждая вакансия может пройти AI-анализ.

Основные результаты:

```text
match_score
is_suitable
analysis_result
status
```

Пример логики:

```text
score >= threshold
        +
вакансия соответствует профилю
        ↓
suitable
```

В противном случае:

```text
rejected
```

Порог соответствия настраивается в интерфейсе/конфигурации.

# ✉️ Генерация писем

Письма создаются только для вакансий, которые прошли анализ как подходящие.

Типичный поток:

```text

 ↓
AI analysis
 ↓
analyzed
 ↓
is_suitable = true
 ↓
cover letter generation
```

Письмо сохраняется непосредственно в базе данных вместе с вакансией.

Это позволяет повторно открыть результат без повторного запроса к модели.

# 🛡️ Принцип «не потакать пользователю»

Одна из важных целей проекта — не просто генерировать красивые тексты, а проверять реальное соответствие вакансии профилю.

Например, если вакансия требует:

```text
Senior Java
5+ years Spring
Kafka
Team Lead
```

а в профиле этих компетенций нет, система должна отражать это в анализе:

```text
suitable = false
```

и показать отсутствующие требования.

Проверка этого поведения включена в ручной чек-лист проекта.

# 🔒 Конфиденциальность

CarrierAssistent ориентирован на локальную обработку.

Профиль:

```text
my_profile.docx
```

и результаты анализа:

```text
chat_history.db
```

хранятся локально.

LLM работает через локальный Ollama.

При этом для получения вакансий из внешних источников приложение должно обращаться к соответствующим сайтам/API/RSS.

Поэтому:

> **AI-анализ выполняется локально, но получение внешних вакансий требует сетевого доступа.**

# 👤 Проект

**CarrierAssistent**

Локальный AI-инструмент для автоматизации поиска работы:

```text
Find
  ↓
Collect
  ↓
Deduplicate
  ↓
Analyze
  ↓
Evaluate
  ↓
Write
  ↓
Review
  ↓
Apply
```

**Главная идея проекта:** использовать локальный AI не просто как генератор текста, а как часть автоматизированного карьерного pipeline, который работает с реальными вакансиями и реальными фактами профиля пользователя.
