# 7.4 Ручное тестирование (реальные вакансии + «не потакает»)

## Подготовка
1. `ollama serve` + модель `qwen2.5:14b-instruct`
2. `my_profile.docx` с **реальными** фактами (без приукрашивания)
3. `streamlit run app.py` или `start.bat`

## Сценарий A — «свой» профиль / близкая вакансия
1. Автопоиск: keywords = ваши навыки (например `python streamlit`)
2. Оценить очередь new (порог 65)
3. **Ожидание:** 1–3 suitable с score ≥ 65; reasons ссылаются на факты из профиля
4. Сгенерировать письмо → проверить:
   - нет клише («с большим энтузиазмом»…)
   - нет выдуманного опыта
   - есть конкретные совпадения с вакансией

## Сценарий B — заведомо чужая вакансия (анти-потакательство)
Вставить вручную (вкладка «Ручной анализ» или save в БД) описание:
- Senior Java / 5+ лет Spring / Kafka / team lead
или
- Kubernetes Platform Engineer / EKS / on-call

**Ожидание после Suitability:**
- `suitable=false`, score обычно **&lt; 50**
- `missing_skills` содержит ключевые требования вакансии
- reasons честные («в профиле нет …»)

Если модель даёт 70%+ на чужую вакансию → ужесточить промпт (см. `tests/test_prompt_ab.py`, вариант B/C).

## Сценарий C — дубликаты
1. Запустить автопоиск дважды с теми же keywords
2. **Ожидание:** второй прогон `saved ≈ 0`, `duplicates > 0`

## Сценарий D — частичный сбой источника
1. Отключить сеть на секунду / выбрать только hh.ru при блокировке API
2. **Ожидание:** остальные источники отрабатывают, ошибки в логе, UI не падает

## Чек-лист «модель не потакает»
- [ ] Нет навыков, которых нет в `my_profile.docx`
- [ ] Soft-skills не маскируют отсутствие hard-skills
- [ ] Чужие senior-вакансии → rejected
- [ ] Письмо начинается с факта/задачи, не с клише
- [ ] В expander «Почему отклонено» видны reasons / missing_skills
